# /check-masters-workload

## Что делает

Проверяет смены мастеров за период на ошибки отметки, искажающие ЗП (неверный `masters`, дубли строк, пустой `masters`, непомеченный режиссёр, смены, отмеченные после выплаты, аномалии часов/ставок), сверяет «живой» расчёт с выплаченным снимком и выдаёт Markdown-отчёт с недоплатами/переплатами и фиксами. Только читает; правки — после подтверждения.

## Как работает

1. **Загрузи актуальный мастер-промпт из Notion:** page `38e612c762af8146b971d2f9bb56c038`
   (https://www.notion.so/38e612c762af8146b971d2f9bb56c038). Действуй строго по нему — там период, базовые понятия расчёта (`calc_visit_payout`: B2C с 01.09.2026 по правилам на руки через `b2c_visit_rate_info`, остальное — `hrm.rates_for_masters`, B2B по ролям), все проверки (A–V) с готовыми FunQL-запросами, правила интерпретации (что норма авто-split, а что дубль; учёт режиссёра и «не учитывать в числе мастеров»), формат отчёта, правила фиксов и гочи FunQL. Кратко: A дубли · B masters · C пустой masters · D режиссёр · E правки после выплаты (+ выплаченное не менялось, что добавилось) · F часы/ставки · G дубли строк ЗП / устаревший прогон · G2 залочка повышенной (только смены до 01.09.2026; с 01.09 — `crm.b2c_rates_check`) · H длительность смены (<15 мин) · I мастер на двух занятиях сразу · J домаркировка задним числом (жёлтый флаг) · K забытый «Ушёл» · L нет ставки → 0 · M продукт без фин.проекта/фин.направления · N админ-смены без разбивки по фин.проектам (молча выпадают из ЗП) · O отметка датирована вне месяца занятия (слепое пятно всех проверок выше — считать ОТ `action_datetime`) · P занятие проведено, но не отмечен ни один мастер (сначала отсечь `class_status` «Отменено» у занятия И продукта) · Q админская ЗП вообще не сгенерирована · R смены админа по 0 ₽ (наблюдение, не недоплата) · S МК из календаря, которых нет в Озме · T программы, начатые до смены ставок (доводить по старым) · U ставка закрыта без продолжения (будущие смены по 0) · V заглушки в составе мастеров.
   > Notion берём через **рабочий** MCP (`c2755fd9-…`), не личный (см. память `feedback_notion_workspace_routing`).
2. Спроси период (по умолчанию — прошлый месяц). Прогони проверки A–V по мастер-промпту.
3. Сформируй отчёт по мастерам с суммами недоплат/переплат и предложенными фиксами. Дождись подтверждения перед любой правкой.

## Критические правила

- **Только отчёт + предложение фиксов.** Авто-правок нет; по каждому пункту — подтверждение.
- **Прод-безопасность.** OzmaDB — продакшн: правки только через `mcp__ozma__transaction` со сводкой.
- **Не удалять записи** — дубль/ошибку обнулять `datetime`/`datetime_end` (по канон-инструкции).
- **Доплата** — перезапуск `staffs.generate_salary_records` по мастеру (сам заводит строку «доплата»). Внесённую в экономику, но не выплаченную строку правят на месте вместе с её `fin.economics`; уменьшение — только так. Ручная доплата (`is_manual=true` + `fin.economics`) — когда генератор неприменим.
- **Переплату по уже выплаченному по умолчанию не вычитать** — показывать наблюдением (решение Бэллы 06.10.2026).
- **Админ-смены без проекта** → проект «Зарплаты» (19), без вопроса; статья «ЗП бэк-офис» ставится сама по `is_admin`.
- **Повышенная ставка (Check G2, только смены до 01.09.2026):** если база залочена не на ту ступень (пакетный ввод задним числом) — чинить выставлением `rate_manually = база(по реальному masters) + надбавка` и `high_rate_prev_manual = null`, `high_rate_applied` оставить `true`. До выплаты ЗП правка `rate_manually` подхватывается генерацией; после — недоплату отдельной строкой.
