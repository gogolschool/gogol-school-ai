# /pay-invoice — счёт → реквизиты для копирования

Задача: человек открывает интернет-банк и копирует поля по одному. Каждое поле — **отдельный code-блок**, без лишнего текста. Ничего не оплачиваем и не отправляем сами.

## 1. Прочитать счёт

PDF / картинку читать через Read. Если файл в `~/Downloads` — путь дают через `@`. Извлечь:
- получатель (полное имя / ИП ФИО), ИНН, КПП (у ИП нет), р/с, банк, БИК, к/с;
- номер и дату счёта, договор (№ и дату), предмет, период;
- итоговую сумму, ставку и сумму НДС («Без НДС» / «НДС не облагается» / 5 % / 22 %);
- УИП/УИН, если в счёте есть («УИП», «Идентификатор платежа», «код 22»);
- **покупателя** — по нему определяется, с какого счёта платить.

Если что-то не читается или противоречит (сумма прописью ≠ цифрами, ИНН не 10/12 знаков, р/с не 20 цифр, БИК не 9) — сказать прямо, не угадывать.

## 2. Плательщик

| Покупатель в счёте | Платит | Где |
|---|---|---|
| ООО «Гоголь Школа», ИНН 9709053471 | ООО | счёт ООО |
| ИП Ромашко / покупатель не указан у аренды, МГТС, Гефеста | ИП Ромашко, сч. 40802810438000016204 | СберБизнес |

Первой строкой ответа — кто поставщик, за что и **кто платит**. Если покупатель в счёте не совпадает с тем, от кого обычно платят этому поставщику, предупредить.

## 3. Формат ответа

Коротко, сверху вниз в порядке полей платёжки:

````
Счёт №… <поставщик> (<суть>). Плательщик — **<ООО «Гоголь Школа» / ИП Ромашко>**.

**Получатель**
```
<имя>
```
**ИНН**
```
<ИНН>
```
**КПП** — <значение в блоке, или «нет (ИП), оставить пустым»>

**Счёт получателя**
```
<р/с>
```
**БИК**
```
<БИК>
```
**Банк:** <банк>, к/с
```
<к/с>
```
**Сумма**
```
<12345.67>
```
**НДС:** <«НДС не облагается» / «22 % — X ₽»>. <ловушка, если есть>

**Назначение платежа**
```
<назначение>
```

Пришли скрин платёжки перед подписанием — сверю.
````

Правила:
- Сумма — без пробелов, с точкой и копейками (`15500.00`), чтобы вставилась в поле.
- В code-блоке только значение, без подписей и кавычек.
- КПП у ИП — не блок, а пометка «оставить пустым».
- УИП/УИН, если есть, — отдельным блоком **«Код (УИН), поле 22»** с подсказкой: в СберБизнес он под «Показать дополнительные реквизиты».

## 4. Назначение платежа

Коротко, до ~150 знаков (длинное не годится): счёт №/дата, договор №/дата, суть сокращённо, период, фраза про НДС.

Шаблон: `Оплата по счету № <№> от <дата>, <суть> по дог. № <№> от <дата> за период <с>-<по>. <НДС>`

- Без НДС → в конце `НДС не облагается`.
- С НДС → `В т.ч. НДС 22% <сумма>` — **но** СберБизнес сам дописывает НДС в назначение, если ставку выбрать в поле; тогда свою фразу не дублировать. Сказать об этом одной строкой.
- Особые форматы поставщиков (если поставщик совпадает):
  - **Озон** (ООО «Интернет Решения», ИНН 7704217370) — строго `Оплата по заказу <№> от <дата>` + `в т.ч. НДС 22% X`; ИНН плательщика = ИНН кабинета 9709053471.
  - **МГТС** (дог. 700143458-1/2019, НДС 22 %) — УИП `000700143458` обязательно в поле 22, не только в назначении.
- Похожие контрагенты: ООО «ГК ГЕФЕСТ» (ИНН 7708347740, Сбер, НДС 5 %) и ООО «ГЕФЕСТ» (ИНН 6949106202, ТБанк, без НДС) — разные юрлица, не путать реквизиты.

## 5. Ловушка НДС (всегда упоминать)

СберБизнес сам подставляет 22 % или запоминает ставку с прошлой платёжки. В ответе одной строкой: «проверь, что стоит <нужная ставка>».

## 6. Сверка скрина платёжки

Когда присылают скрин — сравнить построчно со счётом: получатель, ИНН, КПП, р/с, БИК, сумма, **строка «К оплате (в т.ч. НДС …)»**, назначение, плательщик, УИН (если нужен). Ответ: «Всё сходится» или список расхождений «поле: в платёжке X → нужно Y». Без пересказа совпавших полей.

## 7. Новый поставщик / новая ловушка

Если всплыло что-то новое про поставщика (особый формат назначения, УИП, «счёт ООО, а платили с ИП») — если это правило формата, дописать в раздел 4 этого скилла (в git: `roles/doc-fin-ops/skills/pay-invoice/SKILL.md`); у Бэллы — ещё и в память `reference_sberbusiness_invoice_payment.md`. Если работаешь не у Бэллы — скажи человеку, что новое правило надо передать Бэлле.
