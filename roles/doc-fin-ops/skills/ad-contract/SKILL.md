# /ad-contract

## Что делает

Ведёт рекламный договор по всей цепочке:

1. **Заведение** — контакт в `base.people`, способы связи, счёт в `fin.accounts`, договор в `ad.ad_contracts`, задача в Notion «Документооборот и точка» (процесс «реклама»).
2. **Подписанный PDF** — отмечает чек-бокс «подписать договор рекламы» в задаче, заводит строку в реестр оплаты (Google Sheets), выдаёт набор полей для ОРД.

## Как работает

1. Загружает мастер-промт из Notion: page `32f612c762af8131b78bdeca37876ae1` («📄 Промт: заведение рекламного договора в Озме»).
2. Определяет сценарий: новые данные исполнителя → заведение; PDF подписанного договора → три шага после подписания.
3. Действует строго по мастер-промту, недостающее дозапрашивает.

Мастер-промт в Notion — источник правды. Не работать по памяти: правила и реквизиты меняются, всё ниже — только опора для контекста.

## Опорные точки (полностью — в Notion)

**Номер договора:** `ТИП-ГГ/ММ/ДД-N`, где SE — самозанятый, IE — ИП, дата = дата договора, N — порядковый за день. Проверять по существующим записям `ad.ad_contracts`.

**Дефолты:** дата договора — сегодня; дата окончания публикации — начало + 1 месяц. Дата оплаты дефолта **не имеет** — уточнять.

**Что спрашивать обязательно:** адрес регистрации, ссылка на канал (на канал, не на личку), дата оплаты.

**Реестр оплаты:** Google Sheets `1SnO7zc7_LzXpwELremwGjQTAULY5aGQIxMPFzneeFf4`, вкладка = месяц даты договора (в именах листов бывает пробел в конце — брать из `list_sheets`). Ходим под сервисным аккаунтом `api-service-account@skilful-grammar-489817-b9.iam.gserviceaccount.com`; 403 = таблице не выдан доступ.

**Вид услуг** в реестре берётся из предмета договора. Для рекламных — всегда «Рекламные услуги». Направление (лабы / курс / ППВ) выяснять не нужно.

**Данные для ОРД** (выдаём в чат, сами в ОРД не вводим): заказчик ООО «Гоголь Школа» / 9709053471, исполнитель с ИНН, номер, дата заключения, тип «Договор оказания услуг», вид «Договор на распространение рекламы», дата окончания = конец периода размещения (п. 1.3), сумма из п. 4.1.

## Грабли

- Контакт заводить через `base.people`, **не** через `base.contacts` — иначе реквизиты не подтянутся в шаблон договора.
- `work_entity = 'Cамозанятый'` — enum пишется именно так (маленькая «а»).
- Если контакт уже есть (например, исполнитель — наша студентка) — **обновлять**, а не создавать второй, и не сбрасывать чужие флаги (`is_client` и т.п.), только добавить `is_advertiser`.
- Счёт при наличии — обновлять существующий по `contractor`, не плодить новый.
- Способы связи (`base.communication_ways`) — сначала проверить, есть ли; уникальный индекс по `data + type`.
- Места рождения в Озме нет — не спрашивать и не пытаться записать.
- В назначении платежа в реестре двойные пробелы: `Рекламные  услуги по договору №  {номер} от {дата}` — воспроизводить как есть.
- Отмечать чек-бокс «завести контрагента в ОРД» самостоятельно нельзя — это делает человек.
