# /nalik

## Что делает

Человек пришёл и заплатил наличными в кассу — скилл **просто вносит эту оплату в СРМ**. Ничего не проверяет: ни предыдущие оплаты и дубли, ни право на продукт, ни историю студента.

1. Находит карточку студента (`base.people` + `base.communication_ways`). **Если карточки нет — сначала заводит её** (ФИО + почта и/или телефон) по бартерному промту.
2. Находит продукт в `crm.actions` (по CODE и по `topic`).
3. Создаёт транзакцию `fin.transactions`: `tks_state=CONFIRMED`, `account_to=1310` («"GOGOL School" Касса ООО (Наличные/касса)»), `tks_description="Оплата (наличные/от компании)"`, `comment="внесено Клодиком"`.
4. После триггера `fin.on_confirmed_payment` проверяет, что заявка `crm.actions_for_contacts` подвязалась и стоит в статусе `request_status=6` («Обучается»).
5. Возвращает ID и ссылки на транзакцию, заявку, карточку.

## Как работает

1. Загружает актуальный мастер-промпт из Notion: page `3fa612c762af8162a8f2c1564fb28fee`.
2. Спрашивает у оператора только то, чего не хватает: ФИО покупателя (и контакты, если карточки нет), продукт, сумму. Дата оплаты — по умолчанию сейчас.
3. Перед вставкой транзакции — показывает короткую сводку (кто, что, сумма, дата, название) и ждёт «да».
4. После вставки — отчитывается ID-шниками и ссылками.

## Важно

- Счёт получателя — только `1310` «Касса ООО». `7132` «Касса ИП» — не использовать.
- `account_from` не указываем — триггер сам подставит счёт студента.
- «не шлем» в комментарий **не** ставим: по оферте уведомление об оплате на почту обязательно.
- Бонусы и рассрочку не выспрашиваем — учитываем в названии/комментарии, только если оператор сам сказал.
- Не править вручную — править мастер-промпт в Notion, чтобы изменения попали ко всем.
