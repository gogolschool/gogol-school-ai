# /rassylki

## Что делает

По запросу «внеси / сверь таблицу рассылок на <период>» — берёт будущие продукты из Ozma, формирует и вносит строки в Notion-таблицу регулярных рассылок (для администраторов: они по ней делают рассылки-напоминания).

- **Notion-таблица:** [✉️ Таблица регулярных рассылок](https://app.notion.com/p/e8cdfbb3fdc44ff7995a1750a048f4d6)
  data source: `collection://9538078d-1437-4625-9bb0-c504ba042ef6`
- **Ozma — длительные/пробные:** [fin/monitor_payments_form](https://ozma.gogol.school/views/fin/monitor_payments_form) («отслеживание оплат») = продукты с `is_monitor_payments = true`. Это и есть «раздел будущих программ».
- **Ozma — абонементы:** [crm/announced_classes_table](https://ozma.gogol.school/views/crm/announced_classes_table), `class_type = 18`.
- **Запасной источник:** общий раздел «Продукты» (`crm.actions`) — на случай, если что-то забыли довнести в отслеживание оплат. Прошлые продукты не интересуют, только будущие.

## Когда использовать

Пользователь говорит:
- «внеси / сверь таблицу рассылок» (без периода → **ближайший месяц** от сегодня; иначе — указанный период);
- «проверь / сверь рассылки» по уже внесённым — пересчитать оплаты, снять/поставить статус «Под вопросом», маякнуть по порогам (<6 за 3 дня — всегда; <8 за неделю — длительные/ОУ).

## Период и логика внесения

- «внеси / сверь на ближайший месяц» → вносим **все** запланированные продукты со стартом в периоде, **вне зависимости от числа человек**.
- Продукт (длительная/пробное) с **< 6 оплат** вносим со статусом **«Под вопросом (уточнить о запуске перед отправкой)»** (обычно статус не трогаем — это исключение).
- «проверь/сверь» позже → пересчитать оплаты и маякнуть по порогам (см. «Правило сигналов по оплатам»):
  - стало **≥ 6** → убрать статус «Под вопросом»;
  - **< 6 за 3 дня до старта** (любой продукт) или **< 8 за неделю** (длительные/ОУ) → **сообщить пользователю** (маякнуть), не молчать.

## Источник данных (Ozma) — проверенные запросы

Поля `crm.actions`: `topic` = клиентское «Тема», `name` = CODE, `class_type` = тип,
`action_datetime` = старт первого занятия (UTC), `end_datetime` = конец последнего занятия (UTC),
`is_monitor_payments` = в разделе отслеживания оплат, `class_status` = статус карточки.

**Продукт vs занятие (важно):** у каждого продукта есть одна «родительская» строка
(`topic` заполнена; у длительных/пробных `is_monitor_payments = true`, у абонементов `announced = true`)
и много дочерних строк-занятий с `topic = null` (по одной на день, тот же `name`/CODE).
Считаем по родителю (`topic IS NOT NULL`), даты берём из него (`action_datetime`/`end_datetime`).

**Отменённые не вносим:** `class_status = 5` («Отменено») → пропускаем (даже если `topic` заполнена).
Рабочие продукты обычно `class_status = 2` («Согласовано»).

**Таймзона:** `action_datetime`/`end_datetime` в UTC. Перевести в МСК (UTC+3), взять дату.
Все даты в Notion — это МСК-календарные даты.

### Будущие длительные и пробные + число оплат
```funql
SELECT action AS aid, action=>topic AS topic, action=>name AS code,
       action=>class_type=>name AS type, action=>action_datetime AS starts,
       action=>end_datetime AS ends, count(*) AS paid
FROM crm.actions_for_contacts
WHERE request_status = 6                      -- «Обучается» = оплатившие
  AND action=>is_monitor_payments = true
  AND action=>action_datetime >= '2026-06-22T00:00:00Z'::datetime   -- подставить начало периода
  AND action=>class_type IN (1, 3, 32, 7, 6)
GROUP BY action, action=>topic, action=>name, action=>class_type=>name,
         action=>action_datetime, action=>end_datetime
ORDER BY action=>action_datetime
```
> Продукты с 0 оплат сюда не попадут (нет строк со статусом 6) — их добирать отдельным
> запросом по `crm.actions` (см. ниже), оплат = 0 → тоже «Под вопросом».

### Все будущие продукты (для добора нулевых и сверки)
```funql
SELECT id, topic, name, class_type=>name AS type, action_datetime, end_datetime
FROM crm.actions
WHERE is_monitor_payments = true
  AND action_datetime >= '<начало периода>'::datetime
  AND action_datetime <  '<конец периода>'::datetime
  AND class_type IN (1, 3, 32, 7, 6, 18)
ORDER BY action_datetime
```

**Оплаты на продукте** = число `crm.actions_for_contacts` с `request_status = 6` («Обучается»).
Бартер (19), Waiting List (2), Отмена (9) — **не считаем**.

## Типы продуктов (`class_type`)

| id | Тип | Что делаем | Код в названии рассылки |
|---|---|---|---|
| 1 | Лаборатория | напоминания о старте | `ЛАБ` |
| 3 | Интенсив | напоминания о старте | `ИНТ` |
| 32 | Курс | напоминания о старте | `КУРС` |
| 7 | HEAD | как курс (см. ниже про семейство) | `ХЕД` / `ППВ` |
| 6 | Открытый урок | пробное (см. правило ниже) + бонусы после | — |
| 18 | МК по абонементу | напоминание об оплате за сутки | — |

**HEAD (`class_type = 7`) — семейство, различать по теме/коду:**
- «GOGOL SCHOOL Лидерство» (code `HEAD…`) → `ХЕД`;
- «Практики публичного влияния» (code `PI…`) → `ППВ`;
- «Иначе» (`INACHE`), `ISEEYOU` и прочие → **пока не планируются — спросить пользователя, не вносить молча**.

**Пробное занятие (`class_type = 6`, открытый урок):**
- тема начинается с **«Пробное занятие…»** → обычное пробное;
- тема **«Мастер-класс к курсу …»** → это **тоже пробное** (к HEAD / ППВ / врачам — напр. «Мастер-класс к курсу «HEAD»», «Мастер-класс к курсу «Практики публичного влияния»», «Мастер-класс к курсу «Язык тела и сердца … для врачей»») → **вносить как пробное** (напоминания о занятии + бонусы).
- Если тип неясен — **спросить, не пропускать.**

## Строки в таблице (что вносим)

Поля Notion: `Рассылка` (title) · `Кому` (multi-select) · `Date` · `Text` · `Статус` · `Ответственный`.
`Статус` и `Ответственный` **не заполняем** (это делают администраторы после отправки) —
**кроме** случая <6 оплат → `Статус = «Под вопросом (уточнить о запуске перед отправкой)»`.

Точные значения `Кому`: `тем кто обучается` · `тем кто оплатил за день до старта` ·
`тем кто прошел обучение` · `со статусом "требуется оплата"`.

### Длительная (Лаборатория / Интенсив / Курс / HEAD)
| Рассылка | Кому | Date | Text |
|---|---|---|---|
| `Напоминание о старте {ЛАБ\|ИНТ\|КУРС\|ХЕД\|ППВ} {Тема}` | тем кто обучается | старт − 2 дня | `занятие послезавтра` |
| `Напоминание о старте {…} {Тема}` (то же) | тем кто оплатил за день до старта | старт − 1 день | `занятие завтра` |
| `Перед стартом в ТГ (бот): {ЛАБ\|ИНТ\|КУРС\|ХЕД\|ППВ} {Тема}` | тем кто обучается | старт − 2 дня | `тем, у кого не установлен бот напоминаний` |

> **ТГ-строка** — телеграм-рассылка со ссылкой на бот, **за двое суток** до старта, только для
> **длительных программ** (не для пробных/абонементов).

> ⛔ **«Обратная связь после …» больше НЕ шлём** (формат снят с 08.07.2026). Строку не создаём.
> Если появится решение вернуть — уточнить у пользователя.

> **КУРС / ХЕД / ППВ** (`class_type` 32 и 7): к обоим напоминаниям о старте добавляем
> `/ ссылка на чат курса в срм` → `занятие послезавтра / ссылка на чат курса в срм`
> и `занятие завтра / ссылка на чат курса в срм`. Для ЛАБ и ИНТ — без добавки.

### Пробное (открытый урок)
| Рассылка | Кому | Date | Text |
|---|---|---|---|
| `{Тема}` (как в карточке) | тем кто обучается | старт − 2 дня | `занятие послезавтра` |
| `{Тема}` | тем кто оплатил за день до старта | старт − 1 день | `занятие завтра` |
| `Бонусы после - {Тема}` | тем кто прошел обучение | день пробного (`action_datetime`) | `отложенная отправка после окончания занятия / ТОЛЬКО ТЕМ у кого оплата была без акции (НЕ 1 рубль)` |

### Абонемент (МК по абонементу)
| Рассылка | Кому | Date | Text |
|---|---|---|---|
| `Абонементы, напоминание об оплате` (общее имя, без названия продукта) | со статусом "требуется оплата" | старт − 1 день | `занятие завтра` |

> **Одна строка на каждое МК-занятие по абонементу** (`class_type = 18`), за сутки до его старта.
> Абонементы «только для выпускников» (напр. «Застольный период (только для выпускников)») — тоже
> вносим как обычное напоминание об оплате.

### Отмена программы / открытого урока

Срочная рассылка — пользователь присылает «внеси отмену ОУ/ИНТ/КУРС такой-то».

| Рассылка | Кому | Date | Text |
|---|---|---|---|
| `Отмена ОУ {Тема}` (открытый урок) или `Отмена программы {ИНТ\|КУРС\|…} {Тема}` | тем кто обучается | **дата, когда пользователь прислал инфо** (срочно, не считаем от старта) | `инструкция внутри` |

- В **тело карточки** (page body созданной строки) вставить ссылку на алгоритм:
  [Алгоритм при отмене программы](https://app.notion.com/p/20e612c762af80af974fd5f56e60d8d6).
- **Уже внесённые напоминания** по этому продукту (старт послезавтра/завтра, бонусы и т.п.) →
  статус **«отмена рассылки»**, Text → `отменили оу` (для программ — по аналогии). Эти рассылки не уходят.

### Перенос продукта

Частный случай — пользователь присылает по ситуации. Кому: `тем кто обучается`, Date = дата запроса (срочно),
название `Перенос {ОУ/ИНТ/КУРС} {Тема}`. **Комментарий (Text) и ссылку в карточку — уточнить у пользователя.**
Вероятная ссылка: [Алгоритм при переносе ОУ/продукта](https://app.notion.com/p/232612c762af80a193efc598d3d1b189).

## Правило сигналов по оплатам (важно)

Оплаты = `crm.actions_for_contacts` с `request_status = 6` («Обучается»).

**Маякнуть ответственному (обязательно), если:**
- **< 6 оплат за 3 дня до старта** — **всегда**, для любого продукта (длительные, пробные/ОУ, абонементы).
- **< 8 оплат за неделю (7 дней) до старта** — для **длительных программ и ОУ (пробных)**. К абонементам этот порог не применяется.

**Статус «Под вопросом (уточнить о запуске перед отправкой)»** ставим на строки длительной/пробного
при **< 6 оплат**; при повторной сверке, если стало **≥ 6** — снимаем. (На строках-напоминаниях
абонементов статус не трогаем — они и так для неоплативших.)

## Перед записью в Notion

1. Показать пользователю сводку строк (что вносим), особенно — продукты с <6 и спорные (HEAD-семейство, неочевидные пробные).
2. Создание страниц — `notion-create-pages` в data source `collection://9538078d-1437-4625-9bb0-c504ba042ef6`.
3. Даты пользователю показывать в `ДД.ММ.ГГГГ`; в Notion `Date` — ISO.

## Спросить, не угадывать
- HEAD-семейство кроме Лидерства/ППВ (Иначе, ISEEYOU и пр.).
- Неочевидный тип/пробное.
