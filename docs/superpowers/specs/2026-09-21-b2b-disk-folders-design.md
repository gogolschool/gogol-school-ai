# Папки B2B на Яндекс.Диске — дизайн

Дата: 21.09.2026. Продолжает `2026-09-03-b2b-crm-ozma-design.md` (раздел 4.3 и правка «Папки на Диске» от 04.09) и заменяет их в части структуры папок и механизма создания.

## Зачем

Команда договорилась о единой системе папок для корпоративных клиентов. Раньше автосоздание папок было спроектировано, но не написано: поля под ссылки в Озме есть, заполненных — ноль, кода, который ходит на Диск, нет.

## Решения, принятые 21.09.2026

| Вопрос | Решение |
|---|---|
| Кто создаёт папки | Агенты (`/b2b` и Джангир) через Disk MCP, а не Озма. Токен Диска в Озму не кладём |
| Где работает Disk MCP | На Маке Бэллы (как сейчас) и на сервере `ozma.gogol.school` — для Джангира |
| Когда появляется папка сделки | Сразу при заведении сделки, включая заявки с b2b-сайта |
| Когда появляется «документооборот» | При создании первого продукта из сделки |
| Клиент без бренда | Папка верхнего уровня называется как клиент |
| Сделка без названия | Название собирается по правилу ниже и записывается в сделку |

## 1. Структура

Аккаунт `bella.fatt@gogol.school`, корень `disk:/b2b - корпоративные клиенты`.

```
b2b - корпоративные клиенты/
  Сбер/                                   ← бренд (crm.b2b_brands.name)
    Сбер - Елена - январь 2027 (№16)/     ← сделка
      документооборот/                    ← появляется с первым продуктом
  Яндекс/
    Яндекс — Тест Ангелина · сентябрь 2026 (№17)/
  Вероника Коробова/                      ← клиент без бренда (crm.b2b_clients.name)
    ВИДЕТЬ. СЛЫШАТЬ. ПРИНИМАТЬ. (№10)/
```

Уровня клиента внутри бренда нет. «документооборот» один на сделку, сколько бы продуктов из неё ни создали. Других вложенных папок система не создаёт — аккаунты раскладывают материалы внутри сделки сами.

### Правило названий

- **Папка бренда** = `crm.b2b_brands.name`. У клиента без бренда вместо неё папка с `crm.b2b_clients.name`.
- **Папка сделки** = `{название сделки} (№{id})`. Номер ставится всегда: уровня клиента нет, и сделки с одинаковым названием внутри бренда (сейчас четыре «Заявка с b2b-сайта») иначе слиплись бы в одну папку — Диск на повторное создание отвечает «уже существует», и это считается успехом. Номер же позволяет найти папку после переименования сделки.
- **Пустое название сделки** собирается как `{Клиент} · {месяц год}`, где «Клиент» = `name`, а при заполненной команде — `name — team` (та же договорённость, что для имени продукта от 14.09), месяц и год — по `request_date`, при пустой дате — текущие, месяц словом в именительном падеже. Собранное название агент записывает в `crm.b2b_deals.name`, чтобы в Озме вместо «Сделка 17» стояло то же, что на Диске.
- **Очистка имени**: `/` и `\` заменяются на `-`, управляющие символы убираются, пробелы по краям и повторные схлопываются, хвостовые точки срезаются, длина одного уровня — не больше 200 символов (номер в скобках не обрезается).
- **Переименование сделки** папку не трогает: тула переименования нет, ссылка в сделке остаётся рабочей.

## 2. Disk MCP (`~/YandexDiskMCP`)

Новый тул `create_folder(path)`:

- путь проходит `paths.assert_allowed` — вне белого списка отказ, как у остальных тулов;
- недостающие уровни создаются по одному сверху вниз (API Диска не создаёт вложенные папки одним запросом); корневая папка из белого списка тоже создаётся, если её ещё нет;
- ответ 409 («уже существует») — успех, повторный вызов безвреден;
- возвращает нормализованный путь, приватную ссылку (та же `build_link`, что у `get_link`) и признак `created: true/false`.

Удаления, перемещения, переименования и публичных ссылок по-прежнему нет. Тесты — в стиле существующих: белый список, цепочка уровней, 409, ошибка посреди цепочки, очистка не входит в MCP (имя готовит агент по правилу из раздела 1).

Белые списки (`YANDEX_DISK_ALLOWED_PATHS`):

- Мак: `disk:/Договоры с компаниями (Реализация)` + `disk:/b2b - корпоративные клиенты`;
- сервер: только `disk:/b2b - корпоративные клиенты` — договоры, пароли и персданные серверу недоступны.

Сервер: выкладка штатным `deploy/install.sh` (systemd `yandex-disk-mcp`, порт 8005, токен доступа к MCP в заголовке), `.env` 600. К MCP подключается только клон Джангира (`/home/agentbot/gogol-school-ai-jangir`), остальные боты доступа к Диску не получают. `guard-write.sh` Джангира пропускает `create_folder` без подтверждения: действие безвредное и обратимое руками.

## 3. Озма

- **Новое поле** `crm.b2b_deals.disk_folder` (string) — ссылка на папку сделки; выводится на форму сделки и в таблицу сделок ссылкой. `materials_link` не используем: это многострочные «Материалы» (зум, расшифровка), туда пишут аккаунты.
- `crm.actions.b2b_disk_folder` (есть) — ссылка на «документооборот» сделки. У всех продуктов одной сделки ссылка одинаковая.
- `crm.b2b_clients.disk_folder` (есть) — ссылка на папку бренда, у клиента без бренда — на папку с его именем. Заполняется при создании первой папки сделки этого клиента.
- Ссылки приватные (`https://disk.360.yandex.ru/client/disk/{путь}`, путь восстанавливается из ссылки обратным url-декодированием) и открываются только у тех, у кого есть доступ. Корневую папку Бэлла один раз руками расшаривает аккаунтам в интерфейсе Диска.

Кода в Озме (триггеров, action) не добавляется.

## 4. Кто и когда создаёт

В мастер-промпты в Notion (`/b2b` — `3dd612c762af8131a33aee92712a7fcb`, Джангир — `3db612c762af81fbb9bdd4c06aaacf59`) добавляется блок «Папки на Диске»:

1. **Завёл сделку** → собрать имя по правилу → `create_folder` → записать ссылку в `b2b_deals.disk_folder`; если у клиента пуст `disk_folder` — записать ссылку на папку верхнего уровня; если у сделки было пустое название — записать собранное.
2. **Создал продукт** (шаг 8 цепочки или `/b2b`) → `create_folder` для `…/{папка сделки}/документооборот` → записать ссылку в `b2b_disk_folder` продукта. Если у сделки ещё нет папки — сначала пункт 1.
3. **Добор.** На утреннем обходе (10:00, будни) Джангир создаёт папки сделкам, у которых `disk_folder` пуст, сделка не удалена и не закрыта в отказ (`status=>is_final and not status=>is_success`), и «документооборот» — продуктам с `b2b_deal`, у которых пуст `b2b_disk_folder`. Об успешном доборе не пишет; ошибки — одной строкой в «Сводки».
4. Пока у Джангира `SCHEDULE_ENABLED=0`, добор запускается по просьбе «создай недостающие папки» — у Джангира или в `/b2b`.

Путь папки сделки при доборе «документооборота» берётся не из названия (оно могло измениться), а из ссылки в `b2b_deals.disk_folder`.

## 5. Ошибки

Диск не ответил или отказал — сделка или продукт всё равно заводятся, ссылка остаётся пустой, агент пишет одну строку «папку не создал, доберу», запись подхватывает следующий добор. Отказ белого списка — ошибка настройки, агент сообщает её дословно и не повторяет попытку.

## 6. Первый прогон

1. Тесты MCP локально, затем живая проверка на одной тестовой сделке: папка создана, ссылка открывается, повторный вызов возвращает `created: false`.
2. Список всех 16 сделок показывается Бэлле; папки создаются только отмеченным (сейчас почти все сделки тестовые). Неотмеченным сделкам, чтобы добор их не подхватывал, в `disk_folder` пишется «—».
3. После выкладки на сервер — та же живая проверка от имени Джангира.

## Что не входит

Подпапки внутри сделки и внутри «документооборота», перенос старых материалов из «Договоры с компаниями (Реализация)», автоматическая выдача доступов к папкам, переименование и удаление папок, создание папок из интерфейса Озмы кнопкой.
