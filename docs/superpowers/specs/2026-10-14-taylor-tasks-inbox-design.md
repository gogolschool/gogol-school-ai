# Тейлор: входящие задачи из Telegram в Notion «🧷 Задачи»

Дата: 14.10.2026. Для кого: Валя Шварцер (администратор / куратор программ). Хост: бот Тейлор Свифт (@gs_ops_bot).

## Зачем

Валя получает задачи устно и в переписке и записывает «куда под рукой», потом их теряет. Телефон всегда с ней, а рабочий процесс команды живёт в Notion. Нужно: пишешь или надиктовываешь боту в Telegram, и задача сама оказывается в общей базе задач с её именем. Утром бот напоминает, что горит.

Критерии успеха:
- от сообщения до подтверждения «Записала» — не больше ~15 секунд (обычно ~10);
- ни одна присланная задача не теряется, даже если Notion или Claude недоступны;
- поправить срок или закрыть задачу можно ответом на сообщение бота, не открывая Notion;
- по будням в 10:00 приходит сводка по всем открытым задачам Вали в «🧷 Задачи», включая поставленные ей другими людьми.

## Решения (Бэлла, 14.10.2026)

- Хост — Тейлор, не отдельный бот.
- Куда писать — общая база «🧷 Задачи» (`aefa741ea95f49da9381e9cbaba55c81`), исполнитель Валя.
- Утренняя сводка — сразу, в v1.
- Пользуется ли Валя Тейлор по сайту, неизвестно, поэтому в личке Вали по умолчанию всё считается задачей, а сообщение, которое начинается с «Тейлор…» / «Свифт…», уходит обычному агенту Тейлор.

## Архитектура

Задачи не проходят через агентный прогон Тейлор (Opus + права на сайт и Озму). Причины: скорость (холодный старт агента — десятки секунд), безопасность (фраза «удали ту, про промокод» не должна попасть к агенту с правами на запись) и персона (формат «Проверила / Починила»).

```
личка Вали → bot.py (маршрутизация) → tasks.py
                                        ├─ голос: subprocess scripts/transcribe.py (faster-whisper)
                                        ├─ разбор: claude -p --model haiku --tools "" (JSON)
                                        └─ запись: Notion API (токен «Claude Agents» из .env Тейлор)
scheduler() Тейлор → tasks.digest() по будням 10:00 → личка Вали
```

### Компоненты

**`tasks.py`** — новый модуль рядом с `bot.py` (`/home/agentbot/bots/taylor/`), по образцу `hypotheses.py`: без агента, своё состояние в `state.json` Тейлор (ключ `tasks`). Исходник и тесты в репо `scripts/taylor_tasks/`, деплой через scp (как у `notion_mentions`).

Функции:
- `capture(user, items) -> reply` — пачка сообщений → 1..N задач в Notion → текст подтверждения;
- `edit(user, reply_to_msg_id, text) -> reply` — правка по ответу на сообщение бота;
- `digest(user) -> text` — утренняя сводка;
- `retry_pending()` — дозапись того, что не удалось записать сразу.

**`bot.py`** (правки маршрутизации, остальное не трогаем):
- `TASK_USERS` из `.env`: `TASK_USERS=<telegram_id>:<notion_user_id>[,…]`. Пусто — функция выключена, Тейлор работает как раньше. Добавить человека = одна пара в `.env` + рестарт.
- Сейчас главный цикл берёт только `text`. Для пользователей из `TASK_USERS` в личке дополнительно принимаются: голосовые / аудио / кружки, пересланные сообщения (автор через `forward_info`, перенос из Джангира), подписи к фото и документам.
- Порядок разбора личного сообщения от пользователя из `TASK_USERS`:
  1. `/start` — приветствие в режиме задач («Пиши или говори задачи — запишу в Notion. Утром в 10 пришлю, что горит.»);
  2. начинается с «тейлор» / «свифт» (со склонениями) → обычный агентный путь Тейлор, как сейчас;
  3. `/stop`, `/reset` — как сейчас;
  4. реплай на сообщение бота с подтверждением или сводкой → `tasks.edit`;
  5. «что у меня» / `/tasks` → `tasks.digest` сразу;
  6. иначе → в пачку на захват.
- Склейка: пачка = отправитель; 5 с тишины, не дольше 20 с с первого сообщения. Это ради типичного «переслала сообщение + дописала "до пятницы"». Пока пачка собирается, бот показывает «печатает…».
- `scheduler()`: по будням в 10:00 МСК для каждого пользователя из `TASK_USERS` — `digest`, анти-повтор `sched["tasks_digest:<tg_id>"]`; раз в минуту — `retry_pending()`.

### Захват

1. Голос → `python3 <REPO>/scripts/transcribe.py <файл>` отдельным процессом (около 10 с, память освобождается после завершения). Не расшифровалось → «Не разобрала голосовое, скажи ещё раз или напиши текстом».
2. Разбор: один вызов `claude -p --model haiku --tools "" --strict-mcp-config` с сегодняшней датой и днём недели (МСК). Ответ — JSON-массив:
   `[{"title": "…", "deadline": "YYYY-MM-DD" | null, "time": "HH:MM" | null, "from": "…" | null, "priority": "Срочно" | "Высокий" | null}]`.
   Правила для модели: название — коротко, в повелительном наклонении, до ~80 символов; срок только если он назван («завтра», «до пятницы», «к 20-му»); приоритет только по явным словам («срочно», «горит»); несколько независимых дел — несколько элементов; одна задача с подробностями — один элемент.
3. Фолбэк: разбор упал, превысил таймаут 60 с или вернул невалидный JSON → одна задача, название = первые 80 символов текста, без срока. Захват не блокируется.
4. Запись в «🧷 Задачи»:
   - `Набор` (title) = title;
   - `Исполнитель` = Notion-пользователь из `TASK_USERS`;
   - `Статус` = «Не начато»;
   - `Дедлайн` = deadline (с временем, если оно названо);
   - `Приоритет` — только если определён;
   - `Отдел`, `Проект` не заполняются: бот их не знает, Валя проставит сама при необходимости;
   - тело страницы: исходный текст (расшифровка голосового — с пометкой), «Переслано от: …», «Записано через Тейлор, ДД.ММ ЧЧ:ММ».
5. Notion недоступен → пачка сохраняется в `state.json["tasks"]["pending"]`, Вале отвечаем «Записала себе, в Notion внесу, как он оживёт ✨», `retry_pending` дописывает и присылает обычное подтверждение. Три неудачи подряд дольше часа → ⚠️ Бэлле (`OWNER_CHAT`), не чаще раза в сутки.
6. Подтверждение — одно сообщение в стиле Тейлор, без слова «Проблема»:
   ```
   Записала ✨
   • Позвонить Кучеренко про зал — до пт 16.10
   • Отправить мастерам расписание — без срока
   ```
   Каждая строка — ссылка на карточку. `message_id` подтверждения → список `page_id` в `state.json["tasks"]["msgs"]` (храним 30 дней).

### Правки ответом

Реплай на подтверждение или сводку разбирается тем же haiku в действие:
`{"targets": [номера строк] | "all", "action": "deadline" | "done" | "archive" | "rename" | "priority", "value": …}`.
- «срок на среду» / «перенеси на завтра» → `Дедлайн`;
- «готово» / «сделала» → `Статус` = «Готово»;
- «удали» / «не надо» → `Статус` = «Архив». Страницы не удаляются никогда;
- «переименуй в …» → `Набор`;
- «срочно» → `Приоритет`.
Если в сообщении бота одна строка, номер не нужен; если строк несколько и номер не указан, бот переспрашивает «Какую — 1 или 2?». После правки — короткое «Перенесла на ср 21.10 ✨» / «Закрыла ✨».

### Утренняя сводка

По будням в 10:00 МСК в личку. Берутся задачи «🧷 Задачи», где `Исполнитель` содержит Валю и `Статус` не «Готово» и не «Архив» — то есть все её задачи, не только записанные ботом.
```
Доброе утро ✨
🔴 Просрочено
1. … — было до пн 12.10
📌 Сегодня
2. …
🗓 Ближайшие 3 дня
3. … — чт 16.10
Без срока: 7 — «что у меня» покажет все
```
Пустые блоки не выводятся. Если задач со сроком нет совсем — одна строка «На сегодня задач со сроком нет ✨ Без срока: N». Номера строк привязываются к `page_id` (как у подтверждения), поэтому «2 готово» в ответ на сводку закрывает задачу. Выходные — без сводки.

## Чего не делаем в v1

- Не разбираем отдел и проект.
- Не вкладываем в карточку фото и документы, берём только подпись. Фото без подписи → «Подпиши, что с этим сделать».
- Нет напоминаний в течение дня и вечерней сводки.
- Не создаём задачи другим людям («поставь Свете…»): исполнитель всегда сам автор.
- Нет групповых чатов: режим задач работает только в личке.
