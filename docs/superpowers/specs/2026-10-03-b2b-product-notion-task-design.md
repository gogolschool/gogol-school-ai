# Новый B2B-продукт в Озме → задача Кате в «Документооборот и точка» — дизайн

Дата: 03.10.2026. Согласовано с Бэллой в чате.

## Проблема

Когда в Озме появляется B2B-продукт (из сделки на шаге 8, кнопкой «Создать продукт» или руками),
задачу на документооборот Катя Романова заводит в Notion вручную. Автоматики нет — ни в триггерах
Озмы, ни на сервере (проверено 29.09–03.10.2026).

## Что делаем

Скрипт `b2b_product_tasks.py` на сервере ozma (без LLM: Python + Ozma HTTP API + Notion REST API)
каждые **10 минут** (systemd-таймер) находит новые B2B-продукты и заводит по каждому задачу
в «✏️ Документооборот и точка» (Notion `38940f6e6dc341d79ce55c0ef6db79bc`).
Вариант с триггером Озмы отклонён — Notion-токен в Озму не кладём; вариант «пусть агенты ставят» —
пропустит продукты, созданные руками.

## Какие продукты

`crm.actions`, `type = 'Продукт'` и (`is_b2b` или `class_type = 23` «B2B» или `b2b_deal IS NOT NULL`).

Пропускаются (помечаются виденными без задачи):
- `is_deleted`, статус «Отменено»;
- тестовые — «тест» (без учёта регистра) в названии продукта, клиента или сделки.

**Одна задача на продукт** (у сделки КРОК 4 продукта — 4 задачи; лишние Катя закроет).

**Пауза 15 минут:** продукт, впервые увиденный прогоном, получает задачу не раньше чем через 15 минут —
агенты (/b2b, Джангир) успевают дописать заказчика, контакт, цену и папку.

**Первый запуск** (нет `state.json`): все существующие продукты помечаются виденными, задачи не создаются.

**Дедуп с ручными задачами:** перед созданием ищем в «Документообороте» задачу, у которой
«Ссылка на озму - продукт» указывает на этот продукт (`…?id=<id>`). Нашлась — новую не создаём,
просто запоминаем её.

## Какая задача

Повторяет ручной формат Кати.

| Поле | Значение |
|---|---|
| Задачи (title) | `{Заказчик}/{дата}/{контакт} - b2b`. Заказчик = `customer_name`, иначе клиент B2B; дата = первое занятие, иначе `pl_start_date` (ДД.ММ.ГГ), нет — сегмент опускается; контакт = `customer_contact`, иначе контакт сделки. Нет ни заказчика, ни клиента — `{название продукта} - b2b` |
| Ответственный | Катя Романова (`d5b39214-66db-4761-8ef7-0447637286d0`) |
| Процессы | «b2b клиенты» |
| Status | «Не начато» |
| Дедлайн | дата создания задачи (МСК) + 3 дня |
| Ссылка на озму - продукт | `https://ozma.gogol.school/views/crm/b2b_product_form?id=<id>` |
| Сумма | `price` |
| Ссылка Диск | `b2b_disk_folder` |
| Phone | `customer_contact_tg` (так у Кати в ручных задачах) |
| Иконка | ⭐ |

Тело: блок «Суть» (продукт со ссылкой, сделка, клиент, контакт + tg, аккаунт, старт, сумма,
описание продукта — до 1500 знаков) и стандартный чек-лист Кати (to-do):
организация в Озме → чья форма договора → договор → счёт → согласовать с Бэллой → согласовать
с контрагентом → оригиналы/ЭДО → оплата → Свод программ → акт/УПД + согласовать с Бэллой →
подписать акт/УПД → сканы на Диск.

**Дозаполнение:** 3 дня после создания задачи, если «Сумма» или «Ссылка Диск» в задаче пустые,
а в Озме появились — дописываем. Больше задачу не трогаем.

## Состояние

`state.json` рядом со скриптом: `seen` (id продуктов, обработанных или пропущенных),
`pending` (id → когда впервые увиден), `tasks` (id → {task, created}). Пишется после каждого продукта.

## Ошибки

Как у notion-mentions: 429/5xx Notion — повтор с паузой; любая ошибка прогона → journald;
**3 неудачных прогона подряд** → ⚠️ Бэлле через бот Тейлор. Счётчик сбрасывает первый успешный прогон.

## Инфраструктура

- `/home/agentbot/bots/b2b-product-tasks/` на ozma, user `agentbot`;
  `b2b-product-tasks.service` (oneshot) + `.timer` (каждые 10 мин); исходники и тесты — `scripts/b2b_product_tasks/`.
- `NOTION_TOKEN`, `BOT_TOKEN` — из `.env` Тейлор (интеграция «Claude Agents», уже подключена к «Документообороту»).
- Озма — Keycloak-креды из `~/.claude.json` пользователя agentbot (`mcpServers.ozma.headers`), прямой HTTP API, только чтение.
- `--dry-run` — печатает, что сделал бы, ничего не пишет.

## Вне объёма

Задачи на сделки (не продукты), закрытие задач, синхронизация статусов обратно в Озму, задачи не-B2B продуктов.
