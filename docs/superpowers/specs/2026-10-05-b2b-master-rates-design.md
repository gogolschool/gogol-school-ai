# B2B: ставки мастеров на продукте — дизайн

Дата: 05.10.2026. Статус: согласовано, реализуется.

## Проблема

Договорённость «как мы платим людям на этом продукте» нигде не записана: общие ставки лежат
в справочнике, исключения — ручными правками на каждой отметке, причины теряются. Ошибки
находятся уже после выплаты.

## Решение

Общие правила + видимые на продукте роли и особые ставки. Отметки на занятиях ролей
(Проведение / Разработка / Лид / Аккаунтинг) остаются фактом работы; ставку берём из правил.

### Данные

| Что | Где |
|---|---|
| Уровень мастера Senior / Middle (пусто = Middle) | `base.people.b2b_grade` |
| Таблица ставок проведения: уровень × роль × диапазон участников → ставка на руки, с датой начала действия | `hrm.b2b_conduct_rates` |
| Роль человека на продукте + особая ставка с обязательной причиной | `crm.b2b_product_roles` (продукт × человек × роль) |
| Число участников | «Количество участников по договору» продукта |
| Мини-продукт | тип B2B-продукта «мини-продукт» |

Роли: Основной, Ко-фасилитатор, Разработка, Лид, Аккаунт. Один человек может иметь несколько ролей.
`crm.masters_for_actions` не меняется (уникальность продукт × человек, на неё завязаны вью ЗП);
триггер держит её в синхроне с таблицей ролей.

### Правила (на руки)

- **Проведение** — ставка из таблицы по уровню, роли (основной / ко-фасилитатор) и числу
  участников × часы; налог исполнителя сверху делением на (1 − налог), округление вверх.
  Для основного Middle на самой крупной группе ставка «индивидуально» — нужна особая ставка.
- **Разработка** — 5 % стоимости поровну между разработчиками + налог; на мини-продукте 0.
- **Лид** — 5 % стоимости, без налога. Не обнуляется автоматически; повторный заказ клиента
  подсвечивается в проверке.
- **Аккаунт** — 5 % стоимости с каждого заказа, без налога.
- Приоритет: разовая поправка на отметке → особая ставка на продукте → правило.

### Где видно

- Карточка B2B-продукта: подтаблица «Мастера и ставки» — человек, роль, уровень, ставка,
  откуда она (таблица / особая: причина), сумма за продукт на руки и с налогом, итог ФОТ и его
  доля от стоимости.
- Отчёт `crm.b2b_rates_check` перед генерацией ЗП: отметка без роли, роль без отметки после
  окончания, основной и ко-фасилитатор одновременно, два основных Middle, нет числа участников,
  ставка «индивидуально» без особой, не указан уровень, лид на повторном заказе.

### Включение

Для B2B-продуктов со стартом с 01.11.2026. Более ранние считаются по старым правилам без
изменений (контроль: суммы выплат за сентябрь–октябрь до и после совпадают).

При создании продукта из сделки роль «Аккаунт» подставляется из аккаунта клиента.

## Вне рамок

- B2C: на втором этапе — показать ставки по действующему справочнику в карточке продукта,
  без изменения расчёта.
- Основание ставки в описании записи ЗП не пишем: по точному описанию «аккаунт»/«лид»
  выгрузка в экономику выбирает статью.
