Дата: 29.09.2026. Согласовано с Бэллой в чате.

## Проблема

В «🗂️ Таблице с продуктами» (Notion `1d8612c762af80519c25e6c7b07a19f8`, data source
`collection://9728f62f-5c91-493b-8818-3bcdedae0a82`) людей тегают в **комментариях к карточке**
(например, /add-product: «Продукт согласован ✅ … @Бэлла — заполни финансовые поля»).
Уведомление уходит только во входящие Notion и теряется. Катя Романова и Бэлла живут

data source `collection://093cc271-287d-4273-8588-9a21b994357e`) — там тег виден сразу.

## Что делаем

Скрипт `notion_mentions.py` на сервере ozma (без LLM: Python + Notion API) каждые **10 минут**
(systemd-таймер) находит новые теги наблюдаемых людей в комментариях карточек продуктов
и создаёт/обновляет по ним задачи в «Документооборот и точка».

## Что сканируем

- Карточки таблицы продуктов со статусом **не** «Проведено»/«Отменено» (включая пустой статус
  и подпункты-ОУ).
- Только **комментарии** (page-level обсуждения и ответы в них; блочные обсуждения — тоже,
  если Comments API отдаёт их по `block_id` страницы без обхода блоков — проверить при реализации;
  если нет — только page-level).
- Тег = mention пользователя в rich_text комментария (`mention.type = "user"`).
- Теги в теле карточки, в свойствах и в других базах — **не** ловим.

## Какие задачи

Ключ задачи — пара **(карточка продукта, тегнутый человек)**: одна задача на пару.
Если в комментарии тегнули и Катю, и Бэллу — две задачи.

**Первый тег по паре → новая задача:**

| Поле | Значение |
|---|---|
| Задачи (title) | Название программы (внутр) карточки |
| Ответственный | тегнутый человек |
| Процессы | **«Продукты»** (новый вариант multi-select, добавить в базу) |
| Дедлайн | дата тега (МСК) |
| Status | «Не начато» |
| Тело | цитата комментария, автор тега, дата, ссылка на обсуждение в карточке |

**Повторный тег по той же паре → обновление существующей задачи:**
- в тело дописывается новый блок (цитата, автор, дата, ссылка);
- Дедлайн = дата нового тега;
- если Status был «Готово» или «Проверка» — возвращается в «Не начато».

Если существующую задачу удалили в Notion (архив) — создаётся новая, связь переписывается.

## Состояние и дедупликация

JSON-файл состояния рядом со скриптом:
- `seen_comments` — id уже обработанных комментариев;
- `tasks` — `"<product_page_id>:<user_id>" → <task_page_id>`.

Состояние пишется после успешной обработки каждого комментария (обрыв посередине не даёт дублей
и не теряет теги — необработанный комментарий подхватится в следующий прогон).

**Первый запуск** (нет файла состояния): все существующие комментарии помечаются как виденные,
задачи **не** создаются. Флаг `--backfill-days N` — однократно разобрать теги за последние N дней.

## Ошибки

- Rate limit Notion (429) — пауза по `Retry-After` и повтор.
- Любая ошибка прогона → лог в journald; **3 неудачных прогона подряд** → ⚠️ Бэлле в личку
  через бот Тейлор (токен и chat id из её `.env`). Счётчик сбрасывается первым успешным прогоном.

## Инфраструктура

- Размещение: `/home/agentbot/bots/notion-mentions/` на ozma, user `agentbot`;
  `notion-mentions.service` (oneshot) + `notion-mentions.timer` (каждые 10 мин).
- `NOTION_TOKEN` — интеграция Гермионы (та же, что у сводки гипотез Тейлор). Интеграции нужны:
  доступ к обеим базам и capability «Read comments» (+ insert/update content для задач).
  Если чего-то нет — Бэлла включает один раз в настройках интеграции Notion.
- Ручной прогон: `--dry-run` (печатает, что создал бы, состояние не трогает).

## Вне объёма

- Теги в теле карточки/свойствах, другие базы.
- Автозакрытие задач, ответы в комментариях Notion.
- Мгновенная доставка через Notion webhooks (`comment.created`) — требует публичного HTTPS-приёмника;
  отложено, задержка до 10 минут приемлема.
