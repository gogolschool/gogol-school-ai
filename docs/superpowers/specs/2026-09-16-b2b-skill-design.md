# Скилл /b2b — «Корпоративные клиенты» — дизайн

Дата: 16.09.2026. Согласовано с Бэллой в сессии.

## 1. Задача

Один скилл для работы с разделом «Корпоративные клиенты» в OzmaDB: завести клиента, сделку, продукт, действие, дописать информацию, ответить на вопрос по отчётам. Понимает голосовые. Фраза «Привет, это Вика» переключает разговор на Вику и её клиентов.

Место в системе уже зарезервировано: мастер-промпт Дамблдора (`/b2b-deals`) прямо говорит «клиентов и сделки с нуля заводит `/b2b`».

## 2. Где работает

- **Claude Code** (desktop/CLI) — напрямую.
- **Telegram** — бот Дамблдор (@gs_b2b_bot), форум «GS B2B». Бот загружает оба промпта: `/b2b-deals` (цепочка шагов, утренний обход, сводки) и `/b2b` (всё остальное).

Выкладка бота на сервер — **не в этой задаче** (черновик от 14.09 не выложен). Здесь готовим скилл, промпт и расшифровку так, чтобы бот подхватил их без переделок.

## 3. Устройство

- `.claude/skills/b2b/SKILL.md` — тонкий скилл: описание-триггер и ссылка на мастер-промпт в Notion. Если Notion недоступен — ничего не записывать, сказать одной строкой. Как у `/b2b-deals` и `/check-economics`.
- Мастер-промпт — страница Notion «🤖 Мастер-промпт: /b2b — корпоративные клиенты» в «Базе знаний», рядом с промптом Дамблдора. Источник правды: модель данных, правила записи, запросы отчётов, форматы ответа.
- Разделение с Дамблдором: отметка шагов, «КП на доработке», закрытие сделки, шаги 8 и 9 — по правилам промпта Дамблдора. Промпт `/b2b` на них **ссылается**, не пересказывает, чтобы не было двух версий правил.
- `scripts/transcribe.py` — расшифровка аудио (см. §7).

## 4. Кто говорит — контекст человека

Аккаунты B2B — `base.people.is_b2b_account`: Саша Сучкова 11061, Вика Вавилина 11362, Катя Гусакова 15832, Илья Ромашко 28, Женя Старцев 29.

Как определяется человек, по приоритету:
1. Явная фраза «это Вика / Саша / Катя / Илья / Женя» (и полные имена, фамилии) — действует до конца разговора или до следующей такой фразы.
2. Telegram: чат отправителя → `integration.b2b_bot_users.telegram_chat_id` → `person`; либо тема форума аккаунта.
3. Иначе человек не задан: отчёты — по всем; при записи, где нужен ответственный, — переспросить «кто ты?».

Что даёт контекст:
- «мои клиенты» — `crm.b2b_clients.account_manager = person`;
- «мои сделки», «что горит» — `crm.b2b_deals.responsible` / `crm.b2b_deal_actions.responsible = person`;
- новые клиенты, сделки, действия заводятся с этим человеком как аккаунтом/ответственным (если не назван другой);
- первое сообщение после «это Вика» — короткая сводка: что горит сегодня, к кому пора вернуться.

## 5. Запись

| Что | Как | Подтверждение |
|---|---|---|
| Клиент | `crm.b2b_clients` (бренд, name, team, аккаунт) + юрлицо (`crm.b2b_client_organizations`, контрагент в `base.organizations`) + контакт (`crm.b2b_client_contacts`) | «да» на карточку |
| Сделка | `crm.b2b_deals`: клиент, источник, направления (`crm.b2b_deal_directions`), тип, аудитория, сумма, участники, контакт. Цепочку шагов база стартует сама | «да» на карточку |
| Продукт | только из сделки: action `create_b2b_product_from_deal` (или шаг 8 по правилам Дамблдора). Нет сделки — предложить её завести | «да» |
| Заявка с сайта | строка из «Заявок на B2B-программу» → клиент (найти или создать) + сделка | «да» на карточку |
| Смена аккаунта клиента / ответственного сделки / клиента у сделки | update | «да» |
| Ручное действие со сроком | `crm.b2b_deal_actions` без `stage` | сразу, отчёт одной строкой |
| Итог разговора, перенос срока | update действия | сразу |
| Ретеншн (повод, что предлагаем, бюджетирование), заметки клиента, данные контакта, ссылка на материалы | update только названных полей | сразу |

Правила:
- **Дубли.** Перед созданием клиента — поиск похожих по бренду/названию/команде; контакта — по телефону, email, telegram. Нашёл — показать и спросить, тот ли.
- **Не угадывать.** Непонятно, о каком клиенте или сделке речь, — переспросить одной строкой, ничего не записывая.
- **Голос.** Всё, что пришло голосом и создаёт сущность, — только через карточку-резюме: имена, суммы, даты расшифровка может исказить.
- **Ничего не удалять.** Не трогать договоры, экономику, сайт.
- **После записи** перечитать строку и убедиться, что триггеры отработали (для сделки — появился шаг 2). Не сработало — сказать прямо.
- **Даты** — по Москве, в базу с `+03:00`.

## 6. Отчёты (только чтение)

- Пункты меню раздела: заявки на B2B-программу (`b2b_site_requests_table`), клиенты (`b2b_clients_table`), сделки (`b2b_deals_table`), продукты (`b2b_products_table`), ретеншн (`b2b_clients_to_return`), ближайшие действия (`b2b_whats_hot`), охват по брендам (`b2b_organizations_coverage`), подписчики бота (`integration.b2b_bot_users`).
- Карточка клиента целиком: сделки, продукты, действия по всем сделкам, сумма продуктов, последний контакт, ретеншн.
- Свободные вопросы («сколько у Вики сделок на этапе КП», «что продали Сберу за год») — FunQL по тем же таблицам.
- Контекст человека из §4 применяется как фильтр.
- Формат: коротко, с телефона, без таблиц и SQL в Telegram; в Claude — таблицы допустимы.
- Сумма — по `price` продуктов. Реально поступившие деньги (`fin.transactions` через договоры) — вне первой версии.

## 7. Голос

- **Claude:** `scripts/transcribe.py <файл>` — faster-whisper (уже установлен на Маке), русский, печатает текст. Форматы через ffmpeg: ogg/oga/m4a/mp3/wav.
- **Бот:** на сервере faster-whisper, модель `small`, int8, CPU + ffmpeg. Бот скачивает голосовое, расшифровывает тем же скриптом, отвечает «Услышал: …» и передаёт текст агенту как обычное сообщение. Ожидаются короткие голосовые (до 3 минут); длинные записи встреч — вне первой версии.

## 8. Вне скоупа

- Выкладка бота Дамблдора и подключение к нему `/b2b` и расшифровки.
- Деньги по договорам, договоры, экономика, сайт.
- Длинные записи встреч.
- Удаление записей.

## 9. Проверка

В Claude на боевой Озме:
1. «Привет, это Вика» → сводка по Вике; «мои клиенты» → только её.
2. Голосовой файл с новой сделкой → расшифровка → карточка-резюме → после «да» сделка создана, шаг 2 появился.
3. Тестовый клиент «ТЕСТ /b2b» → проверка поиска дублей на повторе → пометить `is_deleted` после «да» Бэллы.
4. Ручное действие, итог разговора, ретеншн.
5. Два-три отчёта: воронка, ретеншн, карточка клиента.
