# Yandex Disk MCP — поиск документов в папке договоров

**Дата:** 21.08.2026
**Статус:** дизайн согласован

## Задача

Дать агенту возможность находить документы в папке `disk:/Договоры с компаниями (Реализация)` на Яндекс.Диске `bella.fatt@gogol.school` и выдавать на них ссылки. Сейчас доступ есть только через разовые скрипты — постоянного подключения нет.

Полная картина, которую хочет пользователь, состоит из трёх частей:

1. находить документы по программам/компаниям, про которые пишет **← эта спека**
2. вставлять ссылки на документы в CRM (Озма)
3. строить реестры на основании содержимого договоров

Части 2 и 3 сознательно вынесены в отдельные задачи со своими спеками. Здесь строится только часть 1 — и примитивы, на которые части 2 и 3 потом обопрутся.

## Контекст

- OAuth-доступ уже выпущен: приложение «GOGOL School Disk MCP», скоупы `cloud_api:disk.read` + `cloud_api:disk.write`, токен в `~/YandexDiskMCP/.env`. Детали — в памяти `reference_yandex_disk_mcp.md`.
- Папка содержит 159 подпапок по компаниям и 4 шаблона в корне (Договор ООО, Договор ИП, Акт ООО, Счет_оферта).
- В именах папок есть дубли-синонимы (Тинькофф ↔ ТБанк, четыре разных «Яндекс»), пробелы в конце названий, разный регистр и кавычки. Нормализацию этих дублей в рамках этой задачи **не делаем** — только учитываем при поиске.
- В Озме есть `reports.b2b_contracts` (6 записей с апреля 2026) со связью `product → crm.actions`, но **поля под ссылку на документ нет**. Заводить его будем позже, в части 2.

## Архитектура

Повторяем устройство `~/YandexMailMCP`, чтобы не плодить разных подходов:

```
~/YandexDiskMCP/
  pyproject.toml          # mcp, python-dotenv, python-docx, pypdf
  .env                    # токен, client_id, белый список (уже создан, chmod 600)
  src/yandex_disk_mcp/
    __init__.py
    client.py             # HTTP-обёртка над cloud-api.yandex.net, без знания про MCP
    paths.py              # белый список и нормализация путей
    search.py             # нормализация имён и сопоставление, без сети
    documents.py          # ссылки и извлечение текста
    server.py             # определения тулов MCP
  deploy/
    env.example
    install.sh
    yandex-disk-mcp.service
```

Границы модулей:

- **`client.py`** — знает про REST API Яндекса и ничего про MCP. Методы: `list_folder`, `get_meta`, `download_bytes`, `upload_file`. Возвращает питоновские структуры, кидает `DiskError` на HTTP-ошибках. Сеть изолирована в одном методе `_request`, который тесты подменяют.
- **`search.py`** — нормализация имён и сопоставление. Чистые функции без сети плюс кэш дерева. Отдельно от клиента, потому что подкручивать их придётся по мере встречи с реальными именами, и трогать при этом сетевой код не нужно.
- **`documents.py`** — построение ссылок и извлечение текста из `.docx`/`.pdf`. Единственное место, где открывается содержимое.
- **`paths.py`** — единственное место, где решается, разрешён путь или нет. Одна функция `assert_allowed(path)`, которую вызывает каждый тул перед работой. Вынесено отдельно, потому что это защитный периметр: его нужно уметь прочитать и проверить, не читая остального.
- **`server.py`** — определения тулов, валидация аргументов, форматирование ответа. Не ходит в сеть напрямую, только через `client.py`.

## Инструменты

| Тул | Аргументы | Возвращает |
|---|---|---|
| `list_folder` | `path` | Список: имя, тип (файл/папка), размер, дата изменения. Содержимое файлов не читается |
| `find` | `query`, `limit=50` | Совпадения по именам папок и файлов внутри белого списка |
| `get_link` | `path` | Приватная ссылка `https://disk.360.yandex.ru/client/disk/<path>` |
| `read_document` | `path` | Текст из `.docx` или `.pdf` |
| `upload` | `local_path`, `disk_path` | Результат загрузки |

Тулов удаления и перемещения нет — намеренно. Понадобится удалить или переименовать — человек делает это руками в вебе.

### Поиск

Собственный поиск Яндекса (`/resources/files`) ищет по всему Диску и плохо управляем, поэтому `find` работает так: рекурсивный обход белого списка (глубина до 3), затем сопоставление по нормализованной строке — регистр вниз, `ё→е`, кавычки и пробелы схлопнуты, отброшены `ООО`, `АО`, `ИП`, `ЗАО`, `ПАО`. Сопоставление подстрочное, плюс `difflib.SequenceMatcher` для опечаток — из стандартной библиотеки, отдельная зависимость не нужна. Порог 0.62. Дерево кэшируется в памяти процесса на 5 минут, чтобы не долбить API на каждый запрос.

Синонимы (Тинькофф/ТБанк) поиск **не раскрывает** — он вернёт то, что реально совпало. Разбор синонимов — задача агента и, при желании, отдельной задачи по наведению порядка в именах.

### Ссылки

`get_link` строит приватную ссылку из пути, без обращения к API. Публичные ссылки (`PUT /resources/publish`) не поддерживаем вообще: они открывают документ любому, кто получит URL, а в папке лежат договоры с юрлицами.

### Чтение содержимого

`read_document` — единственный тул, который открывает содержимое. Форматы `.docx` (через `python-docx`) и `.pdf` (через `pypdf`); на остальных возвращает ошибку с указанием типа. Сканы без текстового слоя не распознаются — OCR в эту задачу не входит, тул честно скажет, что текста нет.

Массовое чтение (обход папки с открытием всех файлов) в этой части не делаем — оно понадобится в части 3 (реестры) и будет спроектировано там, вместе с решением про передачу персданных наружу.

## Безопасность

Токен имеет `read+write` на весь Диск, включая «Пароли руководителей», трудовые договоры и самозанятость мастеров. Ограничение делается на уровне сервера:

1. **Белый список** — `YANDEX_DISK_ALLOWED_PATHS` в `.env`, разделитель `|`. Любой путь вне списка отклоняется до обращения к API. Проверка идёт по нормализованному пути после схлопывания `..`, чтобы нельзя было выйти за периметр.
2. **Нет удаления** — тула не существует.
3. **Загрузка без перезаписи** — `overwrite=false`. Файл с существующим именем не затирается, возвращается ошибка.
4. **Запись — confirm-first** — правило уровня скилла: перед `upload` агент показывает, что и куда кладёт, и ждёт подтверждения. Совпадает с тем, как у нас устроены записи в economics и возвраты.

## Ошибки

- `401` от API — токен протух или отозван. Сообщение с готовой ссылкой на перевыпуск.
- `404` — путь не существует; в тексте ошибки показываем, что реально лежит в родительской папке.
- Путь вне белого списка — отказ с перечислением разрешённых папок. Не «не найдено»: разница между «нет такого» и «не разрешено» должна быть видна.
- Формат не поддержан в `read_document` — явное сообщение с расширением файла.

## Тестирование

- `paths.py` — юнит-тесты на белый список: путь внутри, путь снаружи, попытка выйти через `..`, регистр, хвостовые пробелы. Это защитный периметр, он тестируется в первую очередь и без сети.
- `client.py` — тесты на замоканных HTTP-ответах: разбор листинга, обработка `401`/`404`.
- Поиск — тесты нормализации на реальных именах из папки: «Тинькофф» vs «ТБанк», четыре «Яндекса», «Озон » с пробелом, `ООО "Бейлиш"` vs `ООО «Рэддэй»`.
- Живая проверка на реальном Диске: найти папку «Ламода Тех», получить ссылку, прочитать шаблон договора.

## Что не делаем

Реестры из содержимого документов, поле под ссылку в `reports.b2b_contracts`, нормализация дублей в именах папок, OCR сканов, публичные ссылки, подключение почтового ящика. Каждое — отдельная задача.
